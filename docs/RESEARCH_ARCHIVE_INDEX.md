## 읽는 방법

- **ORIGINAL HISTORY**는 원래 커밋과 이력을 공개하는 대상이다. **SNAPSHOT**은 원본과 다른 새 커밋이다. 원본 branch/SHA를 그대로 보존하고, 배포 제한 자료 또는 bulk output만 제외했다. 구현·레시피를 포함한 retained 파일은 Git blob와 mode가 원본과 정확히 같다.
- 원본 Task30 이후 이력은 외부 사진·논문 페이지를 포함하는 비교 시트 때문에 로컬에 보존한다. 공개 스냅샷의 parent는 안전한 원본 Task29이다. 이는 Task30 이후의 원래 commit genealogy가 아니다. A 공개 스냅샷은 별도 root다.
- 아래 **LOCAL ONLY** 경로는 실제 로컬 파일이며 GitHub 다운로드 링크가 아니다. 대형 메시·NPZ·3DM·ZIP와 원본 렌더 전체를 추가 추적하지 않았다. 원래 연구 브랜치의 선택된 자체 비교 이미지는 보존했다.
- 문서의 짧은 해시는 표시용이다. [선택 자산 manifest](research_archive/SELECTED_ASSET_MANIFEST.json)에 실제 절대경로·바이트 크기·전체 SHA256이 있다. 이번에 89개 기존 파일을 직접 해시했다. GitHub 파일은 해당 commit의 `git_content_sha256`, 로컬 파일은 실제 디스크 바이트의 `sha256`을 사용한다. Windows 줄바꿈 및 후대 수정 때문에 두 값이 다를 수 있다. 전체 E 드라이브의 완전성 재검증은 아니다.
- [공개 스냅샷 대응 및 제외 목록](research_archive/PUBLICATION_SNAPSHOTS.json), [원본 commit ledger](research_archive/RESEARCH_COMMIT_LEDGER.json), [작업 전 refs/원격/미공개 commit 수](research_archive/GIT_STATE_BEFORE.json), [로컬 보존 bundle](research_archive/LOCAL_PRESERVATION.json). 원본 로컬 SHA에 대응하는 객체가 GitHub에 있다고 가정하지 않는다.

## 누락과 검증 범위

89개 선택 자산의 실제 파일 존재·SHA256을 확인했고 누락은 없었다. GitHub에 연결한 기존 파일 46개는 실제 해당 Git blob의 SHA256도 읽었다. 현재 worktree의 Task24 `hero_design_sprint.py`, Task25 `fold_continuation.py`, Task29 `reference_subdivision.py`는 해당 연구 HEAD보다 후대 버전이다. 역사적 구현은 표의 해당 commit/스냅샷을 사용하며 [버전 차이 기록](research_archive/PUBLIC_ASSET_BLOB_CHECK.json)에 구분했다. 다만 모든 E 드라이브 파일의 완전성, 모든 과거 실행 recipe의 독립 환경 재생성, Astra 미커밋 gate 연구의 전체 소스 일치·공개 권한, 제조 유효성은 이번 작업에서 검증하지 않았다. 외부 source snapshot과 현재 HEAD는 같다고 가정하지 않으며 해당 실행의 request/source identity를 회수해야 한다.

검증은 Git refs/working tree, 경로·SHA, 기록의 판정 근거, 공개 대상 파일/이력의 안전성, retained blob 동일성, 로컬 bundle 검증, `git diff --check`, 원격 SHA readback에 한정한다. 전체 회귀 테스트·형상 생성·렌더·새 가중치 탐색은 실행하지 않는다. 저장된 옛 test count와 face count는 조형 성공 근거가 아니다.

공개 스냅샷에는 제외한 이미지로 향하는 역사적 문서 링크가 남을 수 있다. 기존 연구 문서를 고쳐 과거 기록을 바꾸지 않았으며, 각 스냅샷 root `PUBLICATION_PROVENANCE.json`이 실제 제외 파일과 원본 SHA를 설명한다. 현재 회수 경로는 이 색인을 우선한다.
