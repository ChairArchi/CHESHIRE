The current Mandelbulb/Task36 loop changes control coordinates while subdividing the existing closed surface. Nearest finite-outside targets are field samples, not holes cut in the mesh. Frame/Tissue windows instead change the surface's connectivity and introduce open boundaries before thickening. They answer a different design question and are not evidence that the field loop has gained topological ornament.

The smallest plausible future reuse would be a **single limited frame_bundle study**, not a new engine: pass a selected all-quad shoulder or groove-wall patch directly to the existing worker with a new `action=make` job. This avoids `run.py`'s original fixed selection seed, UNSUBDIV cache and unrelated preservation audit. Input target triangles should be the actual saved source surface; patch quads should retain shared indices. The worker's relief/thickness constants assume the old height-one target, so the height-ten column would require an explicit copy-only unit conversion. Projection can bridge or switch nearby fold walls, and vertex contact alone does not certify fold correspondence. The existing `bilateral` option handles X only and performs a final average of Solidify layer pairs; it should not be silently presented as the current column's constructive X/Y symmetry method.

A distinct integration proposal was considered but **not coded**: replace only selected G2 body quads with the existing frame rims, keep every unselected quad and shared outer index, then Solidify the whole perforated midsurface. This could avoid a separate overlaid network and produce real window walls in one thickened shell. It would also change the source body's interpretation to a hollow thin shell and would need actual connectivity/intersection checks. It would be a G2-derived topology comparison, not a pure G3 continuation or a new fractal generation. No success claim follows from this proposal.

`regional_generation.coarse_edit(kind='opening')` is another existing explicit tunnel operation: it connects two opposing quad mouths and checks Euler change −2. However, it requires `generation == 2` and chooses mouths using world ±Y normals. It is not a direct OVERLAP G3 adapter; relabeling G3 as G2 would conceal its intended scope. It was not invoked.

Recommendation for the present work: **leave these assets preserved and separate**. Continue the existing column-detail comparisons without adding Tissue, windows or layers merely because they are available. No gate generation, code changes to existing operators, new geometry, renderer execution or regression tests were performed for this investigation.
