CHESHIRE / G8 팽창 제어 및 후속 위계 시험 — 2026-10-10

결론
후기 법선 돌출량을 줄이면 겹침으로 뭉쳐 보이던 조직을 더 분리해 읽게 할 수 있다.
그러나 마지막 G8만 조절해서는 큰 덩어리/모듈 배치를 거의 바꾸지 못한다.
초기부터 성장량을 배분하면 외형이 가벼워지지만 미세 조직도 줄어든다.
G1–G4 성공 형상을 보존하고 G5–G8에 국소 배분을 더한 안은 큰 돌출을 남기는
후속 기준 후보다. 별형 반복을 벗어나는 의미적 부모–자식 위계는 아직 구현되지 않았다.
조형적 우열은 사용자가 판단한다. 이번 결과를 완성된 자유 형상 제어로 선언하지 않는다.

A. 동일한 G7 입력에서 G8만 변경한 통제 비교
입력: scratch/column_reference_20261010/published_column_vertex7_results/g07/mesh.json
토폴로지/placement: 기존 G8 weighted Doo-Sabin과 동일. normal extrusion만 변경.
원래 G8의 모든 정점 좌표를 DS 식으로 재구성해 최대 오차 2.38e-12 확인.
재사용하는 출력 topology는 기존 COMPAS 검증 결과와 동일하다.

1 baseline: 기존 돌출량 100%; 폭 5.307028; 정면 점유 pixel 172274.
2 decay_025: 모든 법선 돌출 25%; 폭 5.277619; pixel 169790 (-1.442%).
3 reprocess_only: 법선 돌출 0, weighted DS placement는 유지;
  폭 5.271677; pixel 169290 (-1.732%). 이것은 identity나 일반 smooth DS가 아니다.
4 local_decay: 큰 면의 추가 성장을 더 억제하고 작은 면의 상대적 성장을 남김.
  min(.5,k/(1+(face_perimeter/median_perimeter)^2)).
  k는 area*abs(w10) 가중 평균 multiplier가 .25가 되도록 조절.
  범위 .058505~.5; 폭 5.287422; pixel 170033 (-1.301%).
  같은 전체 1차 돌출 예산인 2번과 배분만 비교한다. 물리 체적을 같게 만든 것은 아니다.

정면/측면 점유는 고정 world frame X/Y [-4.5,4.5], Z [-3,11],
600x1000 이진 투영 triangle union이다. 표면적이나 재료 체적 측정이 아니다.
폭만으로 국소 틈새 충전을 설명할 수 없으므로 실제 동일 카메라 렌더도 함께 비교한다.
모든 안은 G8 917504 vertices / 917506 polygon faces / 1835004 triangles.

재현 (repo root, 반드시 새 output):
.venv/Scripts/python.exe -B scratch/column_reference_20261010/expansion_control.py --output outputs/SOL_NEW_G8_CONTROL
동일 입력·G8 template가 필요하다. 부호/법선/vertex order를 추정만 하지 않고
원래 G8 좌표 재구성 assert를 통과해야 출력한다.

B. 사용자가 추가 요청한 G1부터의 성장 schedule
코드: 기존 published_column.py. 새 연산 없이 normal extrusion 계수만 변경.
설정: paper075_hierarchy_control_8.json
세대 multiplier: [1,.9,.8,.85,.6,.4,.25,.15]. CC placement w1/w2/w3/w4와
DS placement w1, topology 순서는 기존 성공안과 같다.
출력: scratch/column_reference_20261010/published_column_hierarchy8_results/g00…g08
실제 렌더에서 덩어리는 가벼워지나 미세 조직도 약해짐. 같은 별형 구조 배치는 지속됨.
폭 4.867772 (기준 대비 -8.277%), 정면 점유 -12.249%.
실행: .venv/Scripts/python.exe -B scratch/column_reference_20261010/published_column.py --config scratch/column_reference_20261010/paper075_hierarchy_control_8.json --output SOL_NEW_HIERARCHY8

C. 사용자가 추가 요청한 큰 구조 보존 + 선택적 후기 성장
설정: paper075_regional_control_8.json
세대 multiplier: [1,1,1,1,.65,.4,.25,.15]. G0–G4 mesh.json의 바이트 해시가
원래 성공안과 동일함을 regional_prefix_check.json에서 검증했다.
G5–G8 current-face geometry multiplier:
  clip((.5+.5*sqrt(median(perimeter)/perimeter))/(1+2*bend), .25, 2)
  bend = 실제 이웃 face normal과의 1-dot 평균.
  원래 face displacement scale 가중 평균이 1이 되게 정규화한 뒤 곱한다.
현재 큰 면과 큰 굴곡에 추가 성장 예산을 덜 배분한다는 시험 가설이며,
작은 면이 반드시 자식 조직이라는 semantic 보장은 없다.
현재 면 번호/perimeter/bend/multiplier를 g05…g08_growth_field.npz에 저장했다.
출력: scratch/column_reference_20261010/published_column_regional8_results/g00…g08
폭 5.224624 (기준 대비 -1.553%), 정면 점유 -5.415%.
실행: .venv/Scripts/python.exe -B scratch/column_reference_20261010/published_column.py --config scratch/column_reference_20261010/paper075_regional_control_8.json --output SOL_NEW_REGIONAL8

B와 C는 초기 2–4세대 설정도 다르므로, 차이 전체를 국소 mask 효과라고 해석할 수 없다.
이번에는 추가 대규모 ablation을 하지 않는다. 후속 모델은 필요할 때 동일 prefix와
동일 schedule에서 mask on/off를 한 쌍만 비교하면 된다.

검증과 알려진 한계
A 네 안은 실제 OBJ/PLY 재로드에서 finite, closed, winding, face-index 동일,
zero-area 0을 확인했다. self-intersection-free solid 인증은 하지 않았다.
B의 기본 float32 column.ply는 작은 면 8개가 퇴화했다. 원본 mesh.json은 유효하며
column_double.ply를 별도 보존하고 정확한 좌표 roundtrip / zero-area 0을 확인한다.
C도 기본 PLY와 double PLY를 구분해 export_checks.json의 결과를 따른다.
C는 기본 PLY zero-area 0, double PLY 좌표 오차 0 / zero-area 0 확인.
최종 수치: final_measurements.json. 실제 export 검사: export_checks.json.
일반 ASCII PLY loader의 큰 메모리 사용 때문에 한번 MemoryError가 발생했으며,
double PLY 재로드를 NumPy의 bounded parsing으로 바꿨다. 실패 로그도 보존한다.
원래 강한 G7/G8, CGAL full/main-body, 이전 게이트/Tissue는 이 비교로 대체하지 않았다.

후속 방향
성장량 제어는 가능하지만 아직 carrier와 persistent parent hierarchy에 맞춘 제어는 부족하다.
초기 carrier·중간 구조·후기 조직의 역할을 유지하면서 성장/분기/정지 위치를 배분해야 한다.
기존 gate section_mass 및 connected Tissue는 확보된 재료다. 새로 개발하기보다
현재 재귀 연산을 기존 게이트의 support/lintel/transition과 연결하고 값을 조정하는 것이 우선이다.
